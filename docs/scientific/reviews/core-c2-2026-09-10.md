# Core C2 — parameter coordinates and scaling

Status: implementation and numerical qualification complete; independent final review pending. GitHub issue: [#220](https://github.com/tannerpolley/ePC-SAFT/issues/220).

## Bounded capability

C2 qualifies one native contract for active parameter coordinates. It does
not select a fluid model, add a public parameter format, normalize a fitting
coordinate, or qualify equilibrium convergence.

An active coordinate `theta_a` owns explicit native storage slots. A scalar
component family owns one slot. An unordered unlike-component pair in `k_ij`
or `l_ij` owns the two reciprocal row-major off-diagonal slots
`{i*n + j, j*n + i}` for `i != j`; component diagonal slots remain fixed.
An association energy or volume coordinate uses the site-pair matrix instead:
distinct sites own both reciprocal slots, while a same-site pair owns its one
diagonal slot when that association slot is active. Each owned slot is the
linear identity `p_s = theta_a`, so
`d p_s / d theta_a = 1`. The pair coordinate therefore has

`dF/dtheta_a = dF/dp_(i,j) + dF/dp_(j,i)`

and mixed active-coordinate Hessians sum the corresponding raw-slot Hessian
entries. No hidden log, relative, or normalized coordinate is admitted.

Native units are dimensionless for segment count, `k_ij`, `l_ij`, and
association volume; Angstrom for sigma; and Kelvin for dispersion and
association energy-over-k. Conversion from a source unit to native units is
performed before active coordinates. For a linear conversion
`p_native = s_p * p_source`,

`dF/dp_source = s_p * dF/dp_native`,

and `d2F/(dp_source dq_source) = s_p*s_q *
d2F/(dp_native dq_native)`. Supported conversions have no additive offset.

The pure packing coefficient remains independent of `k_ij` and `l_ij`; its
parameter derivative is zero for these families by the defining packing
equation, while the Helmholtz energy tape carries their actual energy and
diameter dependencies.

The implementation must explicitly carry `Lij` through `ParameterFamily`, the
AD tape parameter map, and the model value switch. Association active
coordinates use site-count indexing and are validated separately from
component interactions: a distinct active site pair has exactly its two
reciprocal slots, while an active same-site pair has exactly one slot. An
association coordinate is valid only for an active association slot. The
existing duplicate-slot check remains shared by all families.

The agreed implementation boundary is limited to the existing owners:
`helmholtz_tape.hpp` adds the `Lij` family and makes its `l_ij` tape vector
active; `helmholtz_model.cpp` adds `Lij` to size validation, coordinate value
selection, and the pair/site ownership checks; and
`properties_support.hpp`/`properties_checks.cpp` extend the existing numerical
helper and M7-style registration to represent the two active coordinates.
`request_compile.cpp` keeps the packing derivative zero for `Kij`/`Lij` and
continues consuming the common Helmholtz Hessian. No public binding, input
format, solver, or new scaling abstraction changes.

## Acceptance falsifiers

1. For a smooth binary finite state, active `k_ij` and `l_ij` values and
   gradients are nonzero where their defining energy or cross-diameter terms
   require them. Each active pair gradient agrees with an independent
   perturbation of both symmetric matrix entries together.
2. With independent nonzero `k_ij` and `l_ij` directions, the active Hessian
   action `H*v` agrees with the centered difference of full gradients from
   models whose symmetric matrix entries are perturbed by `+/-h*v`. The
   resulting action includes the mixed `k_ij`/`l_ij` entry.
3. Omitting the reciprocal slot, using a component diagonal pair, using a
   duplicate slot, or using an asymmetric reciprocal pair is rejected at the
   shared model validation boundary. An active same-site association diagonal
   is accepted, and distinct association pairs require both site slots.
4. Independent non-unit source-coordinate scales applied to `k_ij` and `l_ij`
   reproduce the gradient scales and mixed-Hessian product predicted above by
   finite-differencing the existing native model; no new public input
   conversion is added.
5. Existing pure and parameter-gradient reference cases remain unchanged and
   are recorded separately as regression evidence, not as C2 falsifiers.

The binary experiment uses a two-component row-major matrix: `{1, 2}` is the
only valid canonical off-diagonal pair for both `Kij` and `Lij`; `{1}` is a
missing reciprocal, `{0}` is a component diagonal, `{1, 1}` duplicates a
slot, and `{1, 3}` is asymmetric. The four invalid cases `{1}`, `{0}`,
`{1, 1}`, and `{1, 3}` must reject; `{1, 2}` must accept. In the four-site associating fixture, active distinct
pair `{1, 4}` must accept, missing-reciprocal `{1}` must reject, and inactive
same-site `{0}` must reject. A copied fixture with site-0 self-association
activated and finite energy/volume must accept same-site `{0}`; this separates
valid same-site ownership from the inactive-slot rejection.

For the Hessian falsifier, use active coordinates `(k_ij, l_ij)` and a fixed
finite state. With a nonzero active-coordinate direction `v=(0.7,-0.4)`,
perturb both reciprocal matrix entries of each parameter by `+/-h*v` in
independent model instances, retaining the same active set. Compare the base
active-column action `H[:,active]*v` with the centered difference of the
complete gradients from those instances. Use `h=1e-5` and a scale-aware
`5e-6*max(1,|reference|)` bound; the mixed active entry is part of this
vector comparison.

For scaling, define external source coordinates `q` by
`p_native = p_native,0 + S(q-q_0)` with `S=diag(2,3)` for `(k_ij,l_ij)`.
Finite-difference active-coordinate gradients and the active Hessian block at
`q_0 +/- h e_j` must satisfy `g_source=S*g_native` and
`H_source=S*H_native*S` under the same `h` and scale-aware bound. This is an
experiment-only coordinate transform and does not alter the public parameter
document.

The evidence is limited to the stated smooth finite inputs, native parameter
families, and existing conversion factors. It does not establish arbitrary
parameter validity ranges, all derivative orders, equilibrium convergence,
or C3 diagnostic availability.
