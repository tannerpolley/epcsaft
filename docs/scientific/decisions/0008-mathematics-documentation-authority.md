# Mathematical documentation authority

Kind: scientific-documentation

## Context and decision

The transfer audit found valid mathematical requirements mixed with obsolete
interfaces, stage status and incorrect numerical claims. The owner authorized
documentation reconciliation before numerical implementation, using the
repository's existing CSE Markdown layout.

Permanent equation definitions are edited in `engine/docs/equations.md`;
`equations_registry.yaml` is generated by the existing synchronization command.
Markdown with LaTeX equations and precise pseudocode serves both humans and
agents. Additional rendered views must use those same sources. The scientific
context maps EOS conventions, equilibrium formulation, algorithms and fitting
meaning to their permanent owners. ADR 0010 supersedes this decision's former
local implementation-plan ownership clause with GitHub issue ownership.
Superseded setup lives only in Git history
under ADR 0009; dated reviews retain evidence for their inspected snapshot.

This replaces the former YAML-first equation ownership and stage-document
scientific authority. It preserves ADR 0006's polar exclusion and ADR 0007's
directory ownership. Supported corrections from the dated audit define required
mathematics; unresolved method choices remain proposals. Code cannot redefine
correct doctrine merely by behaving differently.

## Consequences and limits

A scientific change updates or explicitly revalidates its equation/algorithm
IDs and domain in the same change as code and numerical evidence. Local checks
reject malformed/duplicate IDs, unresolved references and stale generated
index content. They cannot prove mathematical equivalence or physical validity.
Independent numerical falsifiers and scientific review remain necessary.
No numerical Engine behavior, application qualification, solver method or new
accuracy/runtime threshold was accepted by this documentation decision.
